# Requirements - v1 demo runbook

## Context

Shippy answers procedural questions with citations and runs gated write workflows.
Phases 0-5 are on `main`.
The HTTP surface exists and is tested offline.
There is no README and no single command that proves the system end to end.

Today, proving Shippy means about six manual commands and a Bedrock token.
The captain needs one file that runs the whole thing, prints real evidence, and works with no external credentials.
This phase adds that proof and the runbook around it.

## Scope

### In scope

1. `scripts/demo.sh`: one command, no required arguments, credential-free by default, full HTTP proof with per-step `PASS` or `FAIL` and a non-zero exit on failure.
2. `scripts/demo_app.py`: builds both Chroma collections from the committed corpus, injects a deterministic mock LLM through `get_app`, serves the app on a free local port.
3. An optional `--bookstack` flag that brings BookStack up with Docker, seeds the corpus, runs live ingestion, and repeats the same proof.
4. A real `README.md`: what Shippy is, the cold start, credentials, the Bedrock switch, live ingestion, tests, and lint.
5. This spec directory under `specs/2026-10-19-v1-demo/`.

### Out of scope

1. New runtime dependencies beyond `pyproject.toml`.
2. Changes to the corpus JSON, `docker-compose.yml`, or the behavior of phases 0-5.
3. CI, hybrid retrieval, LangGraph wiring, or the Slack and Gmail adapters.
4. A golden eval suite or a `/stats` endpoint.

## Decisions

**D1 - Proof runs over real HTTP.**
Every proof step uses `curl` against the live server.
No in-process `TestClient` calls appear in the demo path.
The mock LLM is injected through the existing `get_app(provider=...)` seam, so retrieval, validation, auth, and the audit trail are the real code.

**D2 - Demo index builds from the committed corpus.**
`scripts/demo_app.py` reads `scripts/corpus/sops.json` and `scripts/corpus/clients.json` with the same `chunk_page` and `write_collection` helpers the BookStack ingestion uses.
Each corpus page is prefixed with its `# title` line to mirror a BookStack markdown export.
No corpus file changes.

**D3 - The revised corpus page keeps both revisions in the demo index.**
`sop-restocking-fee-current` carries `markdown` and `revised_markdown`.
The demo index stores the original as version 1 and the revision as version 2 under the same `sop_id`.
Chunk ids for the revision get a `.rev2` suffix so Chroma ids stay unique.
This models a stale index that still holds pre-revision chunks.
It lets the version-conflict trap fire on real retrieval, the same way `shippy/eval.py` constructs trap 1.

**D4 - Mock LLM responses are keyed on the question text.**
`MockLLM` matches a configured key against the composed prompt.
The happy-path key is a distinctive fragment of the carrier-claim question.
The quote it returns is a verbatim substring of a retrieved chunk, so the real validator accepts it.
A restocking key returns a fabricated quote as a safety net for the live BookStack path, where the two restocking pages have different `sop_id`s and the version-conflict precheck does not fire.

**D5 - All temporary state leaves the worktree.**
`demo.sh` creates a state directory with `mktemp -d`.
The Chroma path, SQLite database, and server log live there.
A `trap` on `EXIT` stops the server and removes the directory.
Nothing writes under `data/` in the worktree.

**D6 - Credentials are unset for the default run.**
`demo.sh` unsets `ASANA_PAT` and `AWS_BEARER_TOKEN_BEDROCK`.
The app key is generated by the demo itself (`demo-key`).
The default run proves the system needs no external secret.

**D7 - `--bookstack` is optional and documented as such.**
The flag requires Docker and a `.env` with `BOOKSTACK_TOKEN`.
It runs `docker compose up -d`, the existing seed script, and `shippy.ingest.main` into the temp index, then repeats the same eight steps.
The README states plainly that the default path needs none of this.

**D8 - Bedrock switch is an env flag, not a second script.**
`SHIPPY_DEMO_LLM=bedrock` leaves the provider unset so `get_app()` builds `BedrockLLM`.
The mock stays the default.

**D9 - `gh-axi` does not resolve; plain `gh` opens the PR.**
Phase 5 recorded the same substitution.
No new dependency is added.

## Divergence from the brief

None on scope.
One tool-name substitution: the brief says to open the PR with `gh-axi`.
No `gh-axi` binary resolves in this session.
Plain `gh` does the same job.
