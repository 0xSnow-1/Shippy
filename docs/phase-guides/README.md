# Phase Guides

Plain-English walkthroughs of each phase.

One file per phase.
Each file answers four questions.

1. What problem does this phase solve?
2. What did we build?
3. Why is it built that way?
4. What can you do now that you could not do before?

## Who these are for

- You, months later, when the code has faded from memory.
- A reviewer who wants the shape before the diff.
- A recruiter who wants to see how the workflow runs.

The specs in `specs/` are the contract.
These guides are the story.

## Style rules

- Short sentences. One idea each.
- Maximum 20 words per sentence.
- Active voice.
- No jargon without a one-line definition right after.
- Explain the use case as the reader, not as the builder.
- Tables beat paragraphs when comparing things.
